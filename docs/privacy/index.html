    Brainamon stores a library on your devices. Windows desktop, standalone phone, Google Drive mirror and direct-PC modes have different connections, described below. Saving links and notes needs no AI key. External AI processing and Google Drive sync are optional. Reading the bundled policy, software license and notices does not require a provider connection.

    Local data and credentials

    • On Windows, the selected data folder holds saved links, metadata, thumbnails/media, notes, transcripts, reports, canvases, chats and settings. Settings > App shows the data folder. The selected settings home is normally %LOCALAPPDATA%\Brainamon, a reused populated %LOCALAPPDATA%\Content Manager, or the explicit BRAINAMON_HOME. Source runs normally use the repository's data/ and local/; configured locations can differ.
    • API keys, Google authorization, mirror keys and explicitly imported site sessions are kept in the settings home, outside normal library/Drive exports. Windows protects app-managed secret files with current-user DPAPI and access restrictions. Library files themselves are not all encrypted by Brainamon. Protection does not prevent access by someone using your unlocked account or by malware with the same access.
    • Social-site cookies and remembered scraper logins are credentials for the site you choose to access. Import, remembering a login, and copying it for downloads are explicit choices. Forget saved access stops app use and removes app-managed secrets; it does not revoke the site's sessions or delete your original exports, browser profiles or backups.
    • The phone holds library rows, downloaded/opened files, saved offline copies, drafts and pending changes in local browser/app storage. Decrypted library content can remain on the device. The Android app stores pairing/AI keys and Google tokens using Android Keystore-backed encrypted storage and excludes its app data from Android backup. This protection does not describe ordinary browser storage or make downloaded library content encrypted at rest.
    • The desktop error log and in-app diagnostics are local. They may contain file paths, errors, operation details and content from requests/responses. The app does not automatically upload crash reports or analytics to the developer. Review/redact logs or support bundles before choosing to send them; do not include keys, pairing codes or cookie exports.

    Optional AI processing

    AI requests go from the device running the operation to the selected provider or configured OpenAI-compatible/local/proxy endpoint. A proxy may forward them to another provider; a server labelled Local is only local if its configured address actually is. Direct-PC phone mode sends requests to the running PC, which performs the external processing. Standalone/mirror phone own-key features use the providers supported by the phone.

    Depending on the operation, inputs can include questions, chat history, library titles, URLs, descriptions, captions, notes, transcript/report excerpts, retrieved context, supplied images, PDF documents or selected video frames. Own-key phone PDF reading uploads the complete PDF; direct-PC/desktop PDF reading extracts text on the PC. Adding a PDF on the phone starts reading immediately. Search indexing and some Deep research send library text for embeddings; semantic queries send query text. Video analysis can upload extracted audio to OpenAI for transcription and frames/text to the selected analysis provider. Voice notes upload recorded audio to OpenAI for transcription. Picture-reading features send the chosen image to the configured vision provider. Desktop voice-note temporary audio is scheduled for cleanup after processing. Phone recordings can stay queued locally until transcription and saving succeed, and upload automatically when connectivity returns. Video-analysis extracted audio, frames and downloaded media can remain according to the operation's retention options; transcripts/reports remain in the library until deleted. Choosing Claude Code mode in a source installation also uses your separately configured Claude Code service and permissions.

    API credentials authenticate these requests. Provider/API charges are separate from the app's one-time purchase. Provider/proxy terms govern their handling of inputs, outputs, retention and any training use; Brainamon does not promise that a provider deletes immediately, never trains, or keeps data in a particular country. Review your endpoint and provider's current terms before sending sensitive content. Removing a local key stops future use by that copy of the app; it does not revoke the key with its issuer or erase requests already processed externally.

    Requested network access and other apps

    Fetching previews, captions, pages or media contacts the requested sites and their content hosts, transmitting the requested URL and normal connection information such as your IP address and request headers. Chosen site credentials are used only through the relevant access flow. Some previews are requested after a link is pasted/shared. Source sites control their own logs, availability and terms. Browser scraping and video download/analysis run on the PC; a Drive mirror is file sync and does not provide a live PC jobs connection.

    Installed Windows builds check GitHub daily and download updates automatically by default; Settings > App can turn this off. Manual checks/downloads remain available. Checks include the app version; downloads contact GitHub release hosts. Installation always waits for an explicit Install and restart action. Optional tool installation contacts the relevant package/tool/browser download services. These services receive normal connection/download information. The app's local library is not part of an update-check request.

    Sharing a link creates a local draft; Save commits it. Phone edits can queue locally, then travel encrypted through Drive for PC intake when paired with a licensed PC. The encrypted license-control record includes the signed license (holder, optional email, license ID and issue date) plus a short-lived access grant. The paired phone verifies it locally; it is not sent to a licensing server or included in the QR. The PC renews access while running and signed in; removal propagates through Drive, or the last grant expires within one hour when the PC cannot reach Drive. Local phone content/edits remain available while locked. Standalone phone users can optionally back up their library journal encrypted in Google Drive without a PC or license. This backup uses its own key and separate files, even when the account also holds a desktop library. Restoring it requires the same Google account and the phone recovery code; AI keys are not included. Exports and Open in Obsidian hand the selected content to the destination you choose; those exported copies have their own retention. Android QR scanning uses Google Play services' code scanner; Brainamon receives the scanned text and does not request camera permission itself. Android includes Google's code-scanner/ML Kit components. Google's ML Kit terms state that its input processing happens on-device, while the SDK can contact Google for fixes/model and compatibility updates and sends API performance/utilization metrics to Google. See https://developers.google.com/ml-kit/terms and Google's privacy policy at https://policies.google.com/privacy. Exact shipped SDK/device behavior still requires release verification; this app does not promise that every Android dependency makes no external request.

    Optional Google Drive sync

    Google authorization uses drive.appdata, access to Brainamon's hidden app-data area rather than your ordinary Drive files. Drive is off until you connect/enable it. The PC encrypts the mirror contents with AES-256-GCM before upload; paired devices hold the key needed to decrypt them. Standalone phone mode can also store encrypted changes there. Optional Obsidian vault sync sends its configured content through the app's encrypted Drive flow. Google receives your account and connection information and can observe file counts, sizes and change times. Encryption of these contents does not hide that metadata or prevent access by a device/person holding the key.

    Pairing/recovery codes carry library key material. Anyone with the code and the Google account may be able to read the corresponding library. AI-key transfer is separately selected on the PC: selected keys are sealed with a one-time transfer key, expire for collection after 30 minutes and are deleted after successful collection. Failed/offline cleanup can leave expired ciphertext until a later authorized cleanup; expiry is not a promise that every remote byte vanished then. The library key itself does not expire with that transfer. Keep codes and clipboard copies secret.

    Optional Recovery setup uploads passphrase-protected and independent kit-secret-protected envelopes of the library master key to the same hidden Drive area. Scrypt derives the passphrase wrapping key; AES-256-GCM encrypts each envelope. Recovery metadata includes format/version, account, library identity, fingerprint, generation and setup time. The plaintext passphrase and kit secret are not sent to Google or the seller. A recovery kit or explicit phone recovery export contains sensitive key material that you choose where to save. Google sign-in alone cannot decrypt the mirror, and losing every recovery secret/device can make it unrecoverable. New-PC restore downloads the latest available mirror into a separate local library; it is not retained version history or a full machine/credential backup.

    Google's service terms and retention apply to Google-held data. Disconnecting is different from deleting the mirror or revoking another phone's Google authorization.

    Brainamon uses the Google Drive app-data access only to store, read and delete its own encrypted mirror, change, transfer and recovery files for your devices. It does not read your other Drive files and does not send Google user data to the seller. Library content read from the mirror goes to another party only when you direct it, such as a question you send to your own AI provider. Brainamon does not use Google user data for advertising and does not use it to train AI models. Brainamon's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

    Retention and deleting your data

    Local library/settings data remains until you delete it; caches may be trimmed while saved offline copies and pending changes remain. Backups and exports are separate copies. For a full backup or deletion walkthrough, see docs/BACKUP-RESTORE.md supplied with the project documentation.

    1. Review pending phone edits/drafts and keep or send anything you need before removing a copy. Deleting an item/note uses the existing library controls; in mirror mode a PC deletion queued from the phone takes effect on the PC only after intake.
    2. If you want the PC's owned mirrored library files removed from Drive, while still authorized use Settings > Cloud > Disconnect Google Drive... and select Also delete the phone's library copy from Drive, then confirm Disconnect and delete the copy. Wait for successful completion. This targets files identified by the current mirror manifest, not every Drive object, solo journal, vault export, unknown/old file or provider backup. A failed/offline attempt is not completed deletion. Review other retained app data through Google's available controls.
    3. On each phone, More > Unpair (or Remove from this phone in standalone mode) removes that connection. Saved offline files and some pending/local records may remain. To remove all app storage after reviewing unsent work, use Android's app-storage clearing control or uninstall; in a browser clear the Brainamon site's storage. Remove separately exported files yourself. More > Clear the phone's copy only clears a cache: saved offline files and unsent changes stay, and an immediate refresh can download the library again.
    4. On Windows, note the selected data folder in Settings > App and the actual settings home, then Quit fully, including the background/tray process. Interactive uninstall offers to permanently delete local saved data; keeping data is the default, and silent uninstall keeps it. Choosing deletion lists the settings/library folders for a second confirmation, including any discovered custom library outside the settings home. Confirm only after checking every path and any needed backups: everything inside the listed folders is deleted. Cleanup stops on unsafe/unrecognized paths or failures. Review unlisted custom/old folders separately.
    5. Review separate backups, Downloads cookie exports, legacy profiles, logs, other-device copies and exported/Obsidian content. Remove or revoke credentials with their issuers if desired.

    Unpair all phones on the PC queues a key rotation; it finishes only after authorized publication, verification and owned old-file cleanup. It cannot erase cached plaintext on another device or revoke that device's independent Google sign-in. No control promises secure/forensic erasure or automatic deletion from AI providers, marketplaces, their backups or records legally retained.

    選用的 Google 雲端硬碟同步

    Google 授權使用 drive.appdata，也就是存取 Brainamon 專用的隱藏應用程式資料區，而非你一般的雲端硬碟檔案。在你連結並啟用之前，雲端硬碟功能保持關閉。電腦會先以 AES-256-GCM 加密鏡像內容再上傳；配對的裝置持有解密所需的金鑰。手機獨立模式也可在該處儲存加密的變更。選用的 Obsidian 筆記庫同步，會經由應用程式的加密雲端硬碟流程傳送其設定的內容。Google 會收到你的帳戶與連線資訊，並能看到檔案數量、大小與變更時間。內容加密並不會隱藏這些中繼資料，也無法阻止持有金鑰的裝置或人員存取。

    選用的「復原」設定，會將資料庫主金鑰的封套上傳到同一個隱藏的雲端硬碟區域：一份以通關密語保護，另一份獨立以復原組密鑰保護。通關密語的包裝金鑰由 Scrypt 推導；每個封套以 AES-256-GCM 加密。復原中繼資料包含格式與版本、帳戶、資料庫識別、指紋、世代與設定時間。明文的通關密語與復原組密鑰不會傳送給 Google 或賣方。復原組或手機上明確匯出的復原資料含有敏感的金鑰資料，存放位置由你決定。單憑 Google 登入無法解密鏡像；若遺失所有復原密鑰與裝置，可能無法再復原。在新電腦上還原，會將最新可用的鏡像下載到另一個本機資料庫；這並非保留的版本歷史，也不是完整的電腦或憑證備份。

    Brainamon 只使用 Google 雲端硬碟的應用程式資料存取權，為你的裝置儲存、讀取與刪除其自身的加密鏡像、變更、轉移與復原檔案。它不會讀取你其他的雲端硬碟檔案，也不會將 Google 使用者資料傳送給賣方。從鏡像讀取的資料庫內容，只有在你主動指示時才會傳給第三方，例如你傳送給自己 AI 服務商的問題。Brainamon 不會將 Google 使用者資料用於廣告，也不會用來訓練 AI 模型。Brainamon 對於從 Google API 取得之資訊的使用與傳輸，遵守 Google API 服務使用者資料政策，包括「有限使用」的要求。

    資料保留與刪除

    本機的資料庫與設定資料會保留到你刪除為止；快取可能會被清理，但離線副本與待同步的變更會保留。備份與匯出是分開的副本。完整的備份或刪除步驟，請參閱專案文件中附帶的 docs/BACKUP-RESTORE.md。

    1. 移除副本前，請先檢查手機上待同步的編輯與草稿，保留或送出你需要的內容。刪除項目或筆記請使用資料庫原有的操作；在鏡像模式下，從手機排入的電腦端刪除，要等電腦接收後才會生效。
    2. 若要從雲端硬碟移除電腦所擁有的鏡像資料庫檔案，請在仍有授權時使用「設定 > 雲端 > 中斷 Google 雲端硬碟連線…」，並勾選「同時從雲端硬碟刪除手機的資料庫副本」，然後確認「中斷連線並刪除副本」。請等待操作成功完成。此操作針對目前鏡像清單所識別的檔案，而非雲端硬碟中的每個物件、獨立模式日誌、筆記庫匯出、未知或舊檔案，或服務商的備份。失敗或離線的嘗試並不算完成刪除。其他保留的應用程式資料，請透過 Google 提供的控制項檢視。
    3. 在每支手機上，「更多 > 解除配對」（獨立模式為「從此手機移除」）會移除該連線。已儲存的離線檔案與部分待同步或本機記錄可能仍會保留。檢查完尚未送出的內容後，若要移除所有應用程式儲存資料，請使用 Android 的清除應用程式儲存空間功能或解除安裝；在瀏覽器中，請清除 Brainamon 網站的儲存資料。另外匯出的檔案請自行刪除。「更多 > 清除手機副本」只會清除快取：離線檔案與尚未送出的變更仍會保留，立即重新整理也可能再次下載資料庫。
    4. 在 Windows 上，請先記下「設定 > 應用程式」中所選的資料資料夾與實際的設定位置，然後完全結束應用程式，包括背景與系統匣程序。互動式解除安裝會提供永久刪除本機資料的選項；預設為保留資料，靜默解除安裝也會保留。選擇刪除後，會列出設定與資料庫資料夾供第二次確認，包括在設定位置以外找到的自訂資料庫。請檢查每個路徑並確認已有需要的備份後再確認：所列資料夾內的所有內容都會被刪除。遇到不安全或無法辨識的路徑或發生錯誤時，清除會停止。未列出的自訂或舊資料夾請另行檢查。
    5. 請檢查另外的備份、「下載」資料夾中的 Cookie 匯出檔、舊版設定檔、記錄、其他裝置上的副本，以及匯出或 Obsidian 的內容。如有需要，請向發行者移除或撤銷相關憑證。

    在電腦上「解除所有手機的配對」會排定金鑰輪替；只有在經授權發布、驗證並清除所擁有的舊檔案後才會完成。它無法清除其他裝置上快取的明文，也無法撤銷該裝置獨立的 Google 登入。沒有任何操作保證安全或鑑識等級的清除，也不保證能自動從 AI 服務商、銷售平台、其備份或依法保留的記錄中刪除資料。
